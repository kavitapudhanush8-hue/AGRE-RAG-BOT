# FarmAI — Agriculture RAG Chatbot (Starter Build)

A working retrieval-augmented generation (RAG) chatbot for farming questions,
built following the phased plan: knowledge base → chunking → embeddings →
vector search → retrieval → LLM generation → sources → chat history.

This is a **runnable Phase 1–9 prototype**. It answers questions grounded in
a small agriculture knowledge base and cites its sources, with the retrieval
half fully tested and working offline.

## How to run it

```bash
pip install -r requirements.txt
python ingest.py              # builds/rebuilds index.pkl from data/
uvicorn app:app --reload --port 8000
```

Then open **http://localhost:8000** in a browser for a minimal test chat UI,
or call the API directly:

```bash
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"question": "What fertilizer is suitable for rice?"}'
```

Response:
```json
{
  "conversation_id": "...",
  "answer": "...",
  "sources": ["Rice Cultivation Guide"]
}
```

You can also run the retriever + generator directly from the command line
without the API, for quick testing:
```bash
python rag_engine.py
```

## Connecting a real LLM (currently optional)

Right now, if `GEMINI_API_KEY` is **not** set, `/chat` returns the raw
retrieved passages so you can verify retrieval works end-to-end without any
API key. Once you set the key, answers are generated by Gemini, grounded
strictly in the retrieved context (see the system prompt in `rag_engine.py`):

```bash
export GEMINI_API_KEY=your-gemini-api-key
# optional: export FARMAI_MODEL=gemini-2.5-flash   (this is the default)
uvicorn app:app --reload --port 8000
```

## How retrieval works right now (and its known limitation)

To keep this prototype dependency-light and runnable with no downloads or
API keys, `ingest.py` uses **TF-IDF** (classic keyword-frequency vectors,
via scikit-learn) instead of a neural embedding model. It's a genuinely
working retriever — tested above against ~10 sample questions and it
reliably surfaces the right document(s) — but it matches on word overlap
rather than true semantic meaning, so on some phrasings the single
*highest-ranked* chunk within a document isn't always the perfect section
(this is why the pipeline retrieves the **top 4** chunks per question, not
just 1, so the right section is virtually always included in what the LLM
sees).

**To upgrade to real embeddings** (recommended before this goes further than
a prototype), swap two things in `ingest.py` / `rag_engine.py`:
1. Replace `TfidfVectorizer` with a neural embedding call — e.g. OpenAI
   `text-embedding-3-small`, Google's Gemini embedding API, or a local
   model via `sentence-transformers` (`all-MiniLM-L6-v2` is a good, small
   starting model).
2. Replace the in-memory `content_matrix`/`topic_matrix` with a real vector
   database — **Supabase Postgres + pgvector** is a good fit if you're
   already using Supabase (per the original plan), or FAISS/Chroma for a
   simpler local setup.

The rest of the pipeline (`RagEngine.retrieve` → `generate_answer` →
`answer`) doesn't need to change — only the vectors and the storage/search
call.

## What's implemented vs. what's next

| Phase | Status |
|---|---|
| 1. Chat UI | ✅ minimal HTML test UI in `app.py`, ready to swap for React |
| 2. Knowledge base | ✅ 8 topics (rice, cotton, chilli, groundnut, soil, irrigation, pests, diseases) |
| 3. Document upload / text extraction | ⏳ not built — currently reads plain `.txt`; add PDF/DOCX extraction (e.g. `pypdf`, `python-docx`) when you're ready to ingest real source documents |
| 4. Chunking + embeddings | ✅ section-based chunking; TF-IDF embeddings (upgrade path above) |
| 5. Vector database | ⚠️ in-memory TF-IDF matrix; swap for pgvector per the plan |
| 6. RAG retrieval | ✅ combined content + topic similarity search |
| 7. LLM integration | ✅ Gemini via Google Generative AI API, with context-grounded system prompt |
| 8. Source/citation system | ✅ every response returns the source document titles |
| 9. Chat history | ✅ in-memory per `conversation_id`; swap for a real DB table to persist across restarts |
| 10. Crop ML / weather / disease image detection | ⏳ not started — intentionally last, per the plan |

## Suggested next steps (in order)

1. **Expand the knowledge base** — add more crops/topics as `.txt` files in
   `data/`, then rerun `python ingest.py`.
2. **Add PDF/DOCX ingestion** so you can pull from real agriculture
   reference documents rather than hand-written `.txt` files.
3. **Upgrade retrieval** to real embeddings + pgvector (see above) once the
   knowledge base is large enough that TF-IDF's limits start to show.
4. **Persist chat history** to Supabase Postgres instead of the in-memory
   dict in `app.py`.
5. **Build the real frontend** (React, per the original stack) against the
   existing `/chat` and `/history/{id}` endpoints — the API shape won't
   need to change.
6. Only after the above is solid: layer in crop ML, weather, and
   image-based disease detection as separate services feeding into the
   same RAG answer step.
